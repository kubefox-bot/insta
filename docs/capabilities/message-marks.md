# Отметки сообщений

Conversations показывает состояние исходящего сообщения из canonical persistence,
recipient receipts и существующей очереди отправки:

| Символ | Смысл |
| --- | --- |
| Часы | Ожидание сети/ответа или неизвестный результат отправки |
| Серая ✓ | Сообщение сохранено сервером |
| Серые ✓✓ | Клиент получателя принял сообщение выбранного диалога |
| Цветные ✓✓ | Входящая строка пересекала видимую область активной вкладки с focus |
| ! | Окончательная ошибка отправки |

Принятие сообщения из истории или realtime даёт delivered. Read требует реальной
положительной площади пересечения строки и viewport, `visibilityState=visible`
и `document.hasFocus()`. Невидимые строки и ещё не загруженные страницы не читаются.
Это наблюдаемость клиента, а не доказательство человеческого внимания. Фоновая
доставка inbox/push/presence/typing в этот объём не входит.

REST/BFF POST `/api/conversations/:id/receipts` принимает только message IDs и
`delivered|read`. Backend определяет recipient и timestamps. Read включает delivered;
первые времена неизменны. Batch до 50 IDs, квота 120 запросов/min/actor. Чужой,
собственный или отсутствующий ID отклоняет batch целиком. Изменение receipt и
receipt outbox атомарны в Mongo; receipt не меняет sequence и порядок диалогов.

WS `messages.receipts.updated` переносит snapshot авторизованным участникам.
Клиент объединяет состояния монотонно, включая событие раньше message/history.
После reconnect повторяет подписку и canonical sync загруженной истории; polling
для галочек отсутствует. Потеря ответа подтверждения повторяет исходные IDs.
Публикация WS не означает recipient acknowledgment и не обещает exactly-once.

Очередь receipts живёт в памяти и принадлежит actor generation. При logout,
смене аккаунта или dispose прекращаются новые запросы, отменяются owned requests
и освобождаются timers/observers/subscriptions; поздний результат не попадает
в новую сессию. Текст сообщений в receipt queue не сохраняется.

Проверки и их границы описаны в [документации тестирования](../testing.md).
